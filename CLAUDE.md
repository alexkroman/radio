# Notes for Claude

## GitHub in Claude Code cloud sessions

- `gh pr create` and other GraphQL-based `gh` commands fail with HTTP 403. Use the REST API instead, e.g.:
  `gh api repos/alexkroman/radio/pulls -f base=main -f head=BRANCH -f title="..." -F body=@body.md`

## Docker builds and e2e in cloud sessions

- Docker builds reach npm only through the session's HTTPS proxy. `.claude/hooks/session-start.sh` sets `E2E_COMPOSE`, `E2E_BAKE_FLAGS` and `BUILDX_BAKE_ENTITLEMENTS_FS`, so `npm run e2e` just works; for a manual build use `docker buildx bake --load $E2E_BAKE_FLAGS -f compose.yml -f .claude/compose.cloud.yml app` (`docker compose build` can't pass `--allow=network.host`).
- If a Docker build's `npm ci` fails with ECONNREFUSED, the session proxy's port changed (the sandbox was recycled): rewrite `~/.npmrc-docker` from `$HTTPS_PROXY` as `.claude/hooks/session-start.sh` does.
- Run `npm run e2e` after changing anything in the stack; it is the only test of the real system. CI (`.github/workflows/ci.yml`) runs it and pre-commit too.

## Layout

- The station is one 24/7 MP3 stream: Liquidsoap → Icecast mount `/stream`, public at `/stream` via Caddy. `shows/<slug>.md` is a show playing `music/<slug>/` during its `hours: <start>-<end>` (front matter; whole hours, local time `TZ`, end excluded, `22-6` wraps). `radio.liq` builds a source per show and a track-sensitive `switch` on the hours (re-read every minute), then one crossfade, limiter and output. The hours must cover every hour exactly once: `app/schedule.ts` `scheduleProblems`, run by `node app/check-schedule.ts` (pre-commit on `shows/`, and `scripts/deploy.sh`); `radio.liq` logs a severe error for each problem but keeps streaming. Icecast stays because Liquidsoap's own HTTP output (`output.harbor`, 2.3.3) sends no ICY metadata, so players would get no track titles (`test/hunt.spec.ts` checks). Each play (with tags, and the listener count from Icecast's status-json) is appended to `plays/YYYY-MM.jsonl`; the newest play's show is the show on air as far as the app is concerned. Each show also has its own stream (below). `/stream` (and each show's) falls back to `icecast/silence.mp3` (`icecast/config.sh`) so listeners survive a Liquidsoap restart. `scripts/reconcile.sh` (every deploy runs it) reloads Icecast and Caddy, and restarts Liquidsoap when what it runs differs from the files (radio.liq writes the shows it started with to `/tmp/shows`). `test/e2e.sh` runs a deploy's server side for each kind of change (nothing, the app, the Caddyfile, music, hours, a show added and removed; fixture shows and music are volumes there, seeded by the overlay's `seed` service) with a listener on the station through Caddy (`test/listen.ts`) and another on night's own stream, and checks that neither was dropped or heard a pause over 5 s, and that only what had to restart did. The e2e overlay sets `ONAIR_PORT`, which makes `radio.liq` accept `POST /onair` (a slug) to force a show on air; specs use `onAir()` in `test/helpers.ts`. Per-track work hangs off each show's playlist `on_track`: the crossfaded source doesn't mark every track.
- The archive: `radio.liq` also records `radio` (the final bus) with one `output.file` per show (256 kbps, `fallible`, `append=true`, fed by a `switch` that's on while the show is on air by its tracks: from its first track's `on_track` (the crossfade into it) to `ARCHIVE_TAIL` s after the next show's first track (`airing`, `handover`, `recording_on`; tracks put on air by hand don't count, and with no show playing it falls back to the hours) to `archive/recording/<show>-<YYYY-MM-DD>.mp3` (the date the block started). When the switch goes off the file closes (`on_close`; also at startup for blocks that ended while it was down) and moves to `archive/blocks/` if at least `ARCHIVE_MIN_SECONDS` (5 h), else `archive/short/`. Each play's synchronous `on_track` appends the track, at the file's size / 32000 as its offset, to every recording's sidecar but a block in its tail `archive/tracks/<block>.jsonl`; a new file starts with the track playing at offset 0. `scripts/prune-archive.sh` (`archive-prune` service, hourly) enforces retention (< 14 d − 1 h, newest `ARCHIVE_KEEP` a show); sidecars are never pruned. Blocks aren't served as files: each is heard only on its show's own stream.
- Each show's own stream (`radio.liq` `block_stream`): `request.dynamic` picks one of the show's `archive/blocks` at random (not the last, if another), with `annotate:liq_disable_autocue` so it plays as recorded, to Icecast mount `/stream/<slug>` (Caddy passes `/stream/<slug>`; `icecast/config.sh` gives each a silent fallback, reading `/shows`). Its `on_track` loads the block's sidecar; a 1 s `thread.run` compares `elapsed()` with the offsets and, as each track comes up, inserts its title/artist/album (the ICY title) and appends a play to `plays/YYYY-MM.<slug>.jsonl` (`plays.ts` `channelPlays`, counted in the reports at their listeners; never on air for the app). The site plays it from the home page's "Shows", show pages and DJ pages (`ui.tsx` `PlayButton` `now`: `/<slug>/now.json`). A show page's "Past shows" are its airings on the station in the last two weeks, from the play log (`plays.ts` `pastAirings`).
- The statutory license (README "The statutory license"): `radio.liq` enforces the performance complement on the station (`complement_allows`, on played + picked-not-played tracks; `app/complement.ts` checks a play log the same way, in unit tests and over every e2e play); the ICY title, pages, bar and lock screen show title, artist and album; `/about` links the statutes and has the FAQ. The e2e overlay shrinks the windows (`COMPLEMENT_WINDOW` 30, `ARCHIVE_TAIL` 5, `ARCHIVE_MIN_SECONDS` 150, `ARCHIVE_OVERRUN` 60).
- `app/` is one Hono (+ hono/jsx) app: `shows.ts` (reads `shows/*.md`, including the DJs and hours in their front matter), `schedule.ts` (coverage check, what's on and next), `server.tsx` (home: the show and track on air, a compact on-air card, "Shows" (in the order of their hours, each with its own stream's play button to its left, the show's name (linking to its page) over its description), the last 5 tracks, the stream URL in the footer; show pages, with their own stream and past shows; covers; DJ pages `/djs/<dj>`), `reports.tsx` (`/reports`, the public SoundExchange reports, linked from `/about`, not the nav), `login.tsx` (optional `SITE_PASSWORD` signed-cookie login), `plays.ts` (reads the play log), `client.ts` (browser bundle: htmx, the hand-written `style.css`/`tokens.css`, fonts from `@fontsource`; no CDNs). The CSP forbids eval, so no htmx trigger filters.
- Caddy routes GET/HEAD `/stream` and `/stream/<slug>` to Icecast and everything else to the app. `login.tsx` also throttles failed logins.
- Playback in `client.ts` is one plain `<audio>` element, in every browser: play sets its `src` to `/stream` (or a show's, `/stream/<slug>`) and calls `play()` in the tap (iOS needs both; a WebAudio player left AirPlay speakers silent). Track titles and covers come from the play log, not ICY metadata: one 15 s poll in `client.ts` fetches `/now.json` (the track on air and its show) for the player bar and lock screen (and, while a show's stream plays, its `/<slug>/now.json`), and refreshes the page (`ui.tsx` `Poll`) when the track on air changes.
- `app/bar.tsx` is the player bar, rendered in the browser with `hono/jsx/dom` (its `@jsxImportSource` pragma; the rest of `app/` is server `hono/jsx`). `client.ts` feeds it with `setBar()`.
- `app/main.ts` serves `app` from `server.tsx` (built to `dist/server.js`), so `app/*.test.ts` (vitest, `npm test`) can call `app.request()` in-process on `test/fixtures`. Use them for routes, auth and the report; e2e for anything needing the real stack.
- `test/`: `e2e.sh` + `compose.yml` overlay + Playwright specs on `fixtures/`; `global-setup.ts` logs in with `SITE_PASSWORD`.
- Run `pre-commit run --all-files` before committing.
